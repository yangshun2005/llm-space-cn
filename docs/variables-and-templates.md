# 变量与模板

变量和模板让您能够保持提示词的DRY原则和动态性：提取变化或重复使用的内容，通过名称引用它们，并添加条件判断、循环和文件包含等逻辑。这里的所有功能适用于每个文本区域——**系统提示词**、**消息**和**工具结果**——且存储的线程模板保持不变；替换仅在运行时发生。

> 本页基于核心概念中的[变量](./core-concepts.md#variables)部分。请先阅读该部分以了解`{{variable_name}}`的基础知识。

# 变量（回顾）

您在文本中编写`{{variable_name}}`，在运行时LLM Space会将其替换为变量的值。

- **内置变量**自动计算其值：`{{current_date}}`和`{{available_skills}}`。
- **自定义（文本）变量**是您定义一次并可在任何地方复用的`名称 → 值`文本对。
- **JSON变量**保存一个JSON对象或数组，您可以在模板中深入访问并循环遍历——参见下文[JSON变量](#json-variables)。
- **文件内容变量**保存一个文件路径，并在运行时内联该文件的内容——这是`@include`的命名变量形式。参见下文[文件内容变量](#file-content-variables)。
- 变量名必须以字母或下划线开头，并且只能包含字母、数字和下划线。
- 任何不是已知变量的`{{...}}`**保持原样**，因此工具或网络搜索结果中的任意花括号永远不会被破坏。

您可以在**变量**对话框中管理所有这些（从提示词上方的变量标签或编辑器的悬停“检查”按钮打开）。内置变量已为您预置；使用**添加 ▸ 文本**或**添加 ▸ JSON**创建您自己的变量。

# 模板

在普通变量之上，LLM Space支持**Jinja2风格的模板语言**（由Nunjucks驱动）。这增加了宏（以`@include`开头）、条件判断和循环，因此您可以从较小的片段组装提示词并使其适应上下文。

## 模板何时渲染

为确保不受信任的工具输出安全，模板渲染仅对包含以下任一内容的文本生效：

- **块标签**——`{% … %}`（例如`{% if %}`、`{% for %}`）；
- **宏形式**——`{{@ … }}`（例如`{{@include(...)}}`）；
- 使用成员访问、索引、过滤器或调用的**`{{ … }}`表达式**——即包含`.`、`[`、`|`或`(`（例如`{{ user.name }}`、`{{ items[0] }}`、`{{ price | round }}`）。

其他所有内容——普通的`{{variable}}`占位符或无关的花括号——使用更简单的变量替换，永远不会被解析为模板。这就是为什么粘贴的工具结果中零散的`{{a.b}}`是唯一*会*被模板处理的边缘情况（那里的未知值渲染为空而不是保持字面值）；这种情况很少见，但这种权衡换来了独立的字段访问，如`{{ user.name }}`。

如果模板无法解析（例如粘贴的工具结果中有零散的`{%`，或缺少`{% endfor %}`），该文本**保持原样**——损坏的模板永远不会导致运行失败。

## `@include`宏

`@include`将文件内容内联到您的提示词中：

```text
{{@include("~/notes/writing-style.md")}}
```

- 路径可以是**任何绝对路径**，开头的`~`会展开为您的用户主目录。
- 如果文件不存在（或无法读取），它会被替换为**空字符串**——不会报错。
- 包含的内容会**递归渲染**：它本身可以使用`{{variables}}`、控制流，甚至嵌套的`@include`（受深度限制以防止循环）。

**编辑器自动补全：** 在任何提示词编辑器中，输入`{{`并从建议中选择**`@include`**（它会与变量一起出现）——或直接输入`{{@`。应用会插入`@include("path/to/your/file")`并**选中**占位路径，因此您可以立即输入真实路径。

更喜欢可复用的命名版本？使用[文件内容变量](#file-content-variables)而不是重复路径。

## 条件判断

```text
{% if company_name %}
您代表{{company_name}}。
{% elif region %}
按照{{region}}的准则操作。
{% else %}
使用默认策略。
{% endif %}
```

空值或缺失值为假，因此`{% if company_name %}`是仅在变量已设置时包含代码块的便捷方式。

条件是真正的表达式。您可以使用`and` / `or` / `not`组合它们，使用`==` `!=` `>` `<` `>=` `<=`进行比较，使用`in`测试成员资格，并使用内联的`if/else`：

```text
{% if tier == "pro" and not trial %}完全访问权限。{% endif %}
{% if tags and "urgent" in tags %}立即升级。{% endif %}

模式：{{ "详细" if debug else "简洁" }}
```

## 循环

```text
{% for item in ["研究", "草稿", "审查"] %}
{{ loop.index }}. {{ item }}
{% endfor %}
```

在循环内部可以使用：`loop.index`（从1开始）、`loop.index0`（从0开始）、`loop.first`、`loop.last`、`loop.length`。

`{% for %}`还可以带有`{% else %}`，当集合为空时执行，并且您可以遍历对象的`key, value`对：

```text
{% for doc in documents %}
### {{ loop.index }}. {{ doc.title }}
{{ doc.body }}
{% else %}
未提供文档。
{% endfor %}

{% for key, value in settings %}
- {{ key }}: {{ value }}
{% endfor %}
```

您循环遍历的列表/对象通常来自**JSON变量**（下文）、像第一个示例那样的字面列表，或包含的文件。纯文本变量不能作为数据进行迭代。

## 在模板中使用变量

已定义的变量（内置和自定义）可以在模板中按名称使用，未知名称保持字面值：

```text
{% if true %}今天是{{current_date}}。{{unknown_name}}{% endif %}
```

渲染为类似`今天是2026-07-20。{{unknown_name}}`——已知变量被解析，未知占位符被原样保留。

## JSON变量

**JSON变量**保存一个JSON对象或数组，而不是纯文本。在运行时它被解析为真实值，因此模板可以读取字段、基于它们进行分支判断，并循环遍历它们。

在**变量**对话框中使用**添加 ▸ JSON**创建一个，给它一个名称（例如`profile`），并在编辑器中输入JSON（输入时会进行验证）：

```json
{
  "user": { "name": "Ada", "plan": "pro" },
  "features": ["search", "code", "vision"],
  "limits": { "maxTokens": 4096 }
}
```

现在按名称使用它。**字段访问**使用`.`深入访问：

```text
您好{{ profile.user.name }}——您使用的是{{ profile.user.plan }}套餐。
```

**条件判断**读取嵌套值：

```text
{% if profile.user.plan == "pro" %}
您拥有完全访问权限（{{ profile.limits.maxTokens }}个令牌）。
{% else %}
您使用的是免费套餐。
{% endif %}
```

**循环**遍历数组（对象使用`key, value`）：

```text
已启用的功能：
{% for feature in profile.features %}
- {{ loop.index }}. {{ feature }}
{% endfor %}
```

将**整个变量**引用为`{{ profile }}`会以**美化格式的JSON**打印——这对于向模型转储结构化上下文非常方便：

```text
上下文：
{{ profile }}
```

注意事项：

- 字段访问可以**独立使用**——`{{ profile.user.name }}`即使在没有`{% %}`标签的文本中也能渲染（这就是[模板何时渲染](#when-a-template-is-rendered)中`.` / `[` / `|` / `(`触发器的用途）。
- **缺失**字段渲染为空（`{{ profile.nope }}` → ``），因此当字段可能不存在时请使用`{% if %}`进行保护。
- 如果JSON**无效**，编辑器会显示解析错误，变量在运行时保持未解析状态（其占位符保持字面值），而不会导致运行失败。

## 文件内容变量

**文件内容变量**保存一个文件**路径**，在运行时它被替换为该文件的**内容**——与`@include`功能相同，但作为可复用的命名变量而不是内联宏。

在**变量**对话框中使用**添加 ▸ 文件内容**创建一个，然后通过点击**浏览…**（打开操作系统原生文件选择器）或直接输入来设置路径——开头的`~`会展开为您的用户主目录，路径**不会**检查是否存在。

按名称引用以内联文件：

```text
{{ writing_style }}

请遵循上述风格指南。
```

- **缺失或不可读**的文件内联为**空字符串**——不会报错。
- **空路径**使占位符保持字面值（如同未设置的变量）。
- 内容以**原始**形式内联——文件中的变量和模板标签**不会**被重新渲染。如果您需要文件自身的`{{variables}}` / `{% … %}`被渲染，请使用[`@include`](#the-include-macro)（它会递归渲染）。
- 在仅显示的Web查看器中没有文件系统，因此文件内容变量不会内联任何内容。

当同一个外部文件被多个提示词/线程引用，且您更愿意在一个地方管理路径而不是重复`@include("…")`时，请使用文件内容变量。

## 过滤器

过滤器使用`|`转换值。一些有用的示例：

```text
{{ name | default("there") }}          {# 空/未定义时的回退 #}
{{ profile.features | length }}         {# 3 #}
{{ profile.features | join(", ") }}     {# search, code, vision #}
{{ profile.user.name | upper }}         {# ADA #}
{{ notes | truncate(200) }}
```

过滤器从左到右链式使用：`{{ items | sort | join(", ") }}`。

## 更完整的示例

结合`@include`角色、JSON变量`brief`和控制流：

```text
{{@include("~/prompts/persona.md")}}

## 任务
{% if brief.audience %}面向{{ brief.audience }}撰写。{% else %}面向普通受众撰写。{% endif %}
语气：{{ brief.tone | default("中性") }}。

## 来源（{{ brief.sources | length }}）
{% for src in brief.sources %}
- [{{ loop.index }}] {{ src.title }} — {{ src.url }}
{% else %}
（未提供）
{% endfor %}

## 检查清单
{% for step in ["大纲", "草稿", "引用来源", "校对"] %}
- [ ] {{ loop.index }}. {{ step }}
{% endfor %}

当前日期：{{current_date}}
```

……其中`brief`是一个JSON变量，例如：

```json
{
  "audience": "engineers",
  "tone": "concise",
  "sources": [{ "title": "RFC 9110", "url": "https://www.rfc-editor.org/rfc/rfc9110" }]
}
```

# 编辑器支持

提示词编辑器（系统提示词、消息和工具结果）理解模板语法：

- **高亮**——`{{variable}}`占位符以琥珀色高亮，`{% … %}`标签以紫色高亮，使模板结构与周围文本区分开来。高亮纯粹是语法层面的；它从不验证名称。
- **变量 / `@include`补全**——输入`{{`获取可用变量列表以及**`@include`**。选择`@include`会插入`@include("path/to/your/file")`并选中占位路径，准备直接输入覆盖。（输入`{{@`会直接缩小到`@include`。）
- **标签补全**——输入`{%`获取块标签：`if`、`elif`、`else`、`endif`、`for`、`endfor`、`set`、`raw`、`endraw`。每个标签插入完整的`{% … %}`标签，光标放置在您继续输入的位置（例如`{% for ‸ in  %}`）。

# 渲染、存储和运行历史

- 替换在**运行时**执行；保存的线程保留原始的`{{...}}`和`{% ... %}`源代码。
- 一旦消息或工具结果运行过，其渲染输出会**为该次运行的历史冻结**，因此即使包含的文件或时钟后来发生变化，回放和比较也能保持字节稳定。编辑源文本会在下次运行时重新渲染。
- 在仅显示的Web查看器中没有文件系统，因此`@include`解析为空字符串。

# 提示

- 将可复用的代码块（角色、语气、共享约束）保存在Markdown文件中，使用`@include`引入，或将简短片段存储为自定义文本变量。
- 将结构化、复用的数据（配置、记录、功能标志）放入**JSON变量**，并从中驱动`{% if %}` / `{% for %}`，而不是手动编辑多个提示词。
- 使用`{% if %}`切换可选部分，无需维护多个提示词。
- 使用`{% if data.field %}`或`| default(...)`保护可能缺失的字段——缺失字段渲染为空。
- 如果模板表面意外渲染为纯文本，请检查其标签是否平衡——无法解析的模板会静默回退到原始文本。
